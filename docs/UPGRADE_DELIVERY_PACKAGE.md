# AAS V2（2026-11-06）改造候选源码包与现场验证

**定位：受控功能试用 / Windows 待验收候选，不是 Stable 版。** 源码候选包由本地功能分支 `feat/aas-p3-csv-quality-ux` 生成。输入 ZIP 不含 `.git`，本轮从 ZIP 建立本地 Git 基线；当前没有配置 AAS 远端，不声称已推送或发布 GitHub Release。

## 1. 包含什么、不包含什么

- 包含：`AAS/` 内完整候选源码、网页前端、服务端、Windows 启动与测试脚本、回归测试、`datasets/templates/` 数据映射模板和 `datasets/README.md`。
- 包内 `AAS/UPGRADE_SHA256_MANIFEST.json` 记录每个源码文件的 SHA-256；`LOCAL_TEST/Verify-UpgradeSourceZip.py` 在解压前逐文件核查。
- **不包含** `.venv/`、`.git/`、数据库原件、原始遥测文件、`models/` 模型、历史报告与运行输出、机器密钥和配置凭据。源码包不能代替历史数据库或离线依赖介质。
- 对非正常编码而无法在 ZIP 中保真表示的旧文件名采取跳过策略；交付核心程序、模板、改造文档与测试应在清单中。

## 2. 从新机器安装（Windows 10/11，PowerShell 5.1）

前置：Python 与所需依赖的离线安装介质已准备好；纯源码 ZIP **没有**自带离线 wheelhouse。目标机器需要可用的 Python 启动器 `py`。如果离线安装，先按照现场介质的环境安装方案用本地 wheel 包安装全部依赖；不要让无网络设备直接访问 PyPI。

1. 使用 `Get-FileHash .\AAS_V2_P3C_TaskDiagnostics_20261106_candidate_v3.zip -Algorithm SHA256` 比较交付通知中提供的**整个 ZIP** SHA-256；建议在解压之前用独立取得的哈希核对文件身份。
2. 如已持有验包脚本，可以提前运行 `py LOCAL_TEST\Verify-UpgradeSourceZip.py .\AAS_V2_P3C_TaskDiagnostics_20261106_candidate_v3.zip --expected-sha256 <交付包哈希>`；否则先核对外部哈希，再解压，从包内 `AAS/LOCAL_TEST/` 运行脚本校验原 ZIP。
3. 将 ZIP 解压至专用新目录，例如 `D:\AAS_Upgrade_Trial`，应得到 `D:\AAS_Upgrade_Trial\AAS\README.md`，**不要把它直接覆盖在老运行目录上**，也不要多嵌套一层 `AAS/AAS`。
4. 在新目录 `AAS/` 下按既有 `LOCAL_TEST\Install-TestEnv.ps1` 安装环境；网络受限时先使用离线依赖方案。命令：`powershell -NoProfile -ExecutionPolicy Bypass -File .\LOCAL_TEST\Install-TestEnv.ps1`。
5. 若需浏览/训练旧历史数据，在**备份旧数据库后**将可用的 V2 主库副本放到新目录 `datasets/aas_telemetry_v2.sqlite`；如果只有原始 `.csv.gz` 和 labels，则依 `INSTALL_TARGETS_V2.md` 从头构建。模拟 CSV 工作区首次使用时由功能服务按需初始化独立模拟库。
6. 启动：`powershell -NoProfile -ExecutionPolicy Bypass -File .\LOCAL_TEST\Start-AAS-UI.ps1`，打开 `http://127.0.0.1:8765`。主库缺失时不要把历史库空白界面误判为故障；先执行数据库安装/导入步骤。
7. 回归：`powershell -NoProfile -ExecutionPolicy Bypass -File .\LOCAL_TEST\Run-UpgradeTests.ps1`；然后再执行原项目 `Run-LocalTests.ps1 -Mode smoke`、`-Mode full`。后两项为原系统宽范围门禁，必须如实记录失败项。

## 3. 最小现场操作验收单

| 项目 | 手工验证过程 | 验收证据 |
| --- | --- | --- |
| 导入与导出 | 故障模拟界面导入多列 CSV，检查列及首末帧，导出完整版并比较列头、总帧数 | 原/导出 CSV、帧数截图 |
| 复合注入 | v0 的第 10～20 帧注入故障 A，保存 v1，再于第 15～30 帧注入故障 B 保存 v2 | v0/v1/v2 不可变、重叠区实际数据与标签 |
| 历史来源 | 选一个历史来源，指定闭区间起止帧，预览、保存、导出；点击「继续注入」检查生成工作区版本 | 历史记录 ID、导出 CSV、两段注入记录 |
| 数据训练 | 训练页导入 CSV，确认数值列、用途、时间轴，完成小样本真实训练 | 模型 ID、日志、归档报告 |
| Excel / CSV 格式识别 | 分别用 UTF-8 BOM＋TAB、GB18030＋分号、中文说明列及 CSV.GZ 文件，在训练/评估、历史数据库导入和模拟故障工作区分别检查同一组样本：UTF-8 BOM＋TAB、GB18030＋分号、中文表头、CSV.GZ。核对识别编码/分隔符，**勾选已核对格式**后才能预检/导入。修改格式必须重新检查；历史导入的列映射修改只需重新预检。 | 列映射、格式确认状态、原始文件 SHA256、错误定位及页面截图 |
| 模型评估 | 从**同实例**导出认证 `.aas.zip` 模型包再导入，选择有真值的测试 CSV 评估 | 评估指标、模型/来源契约、任务日志 |
| 无标签仅推理 | 保留模型训练 CSV 原来源；另导入**独立采集且内容不重复**、物理语义相同的无标签测试 CSV；选择已发布模型，预览有效帧并执行「开始仅推理（无真值）」 | 分数/算法报警曲线、`evaluation_mode=score_only`、`ground_truth_available=false`、空监督指标；小样本输入快照可核验，大样本仅保留输入摘要；未进行整库前后快照核验时状态应为未知 |
| 报表恢复 | 关闭网页与服务、重启，在「任务查询与导出」找回先前任务、打开并导出结果 | 运行 ID、重启前后列表 |
| 历史数据库 | 先按 raw/unspecified/simulation 浏览非同窗口参量；训练/评估保持数据对齐和标签资格约束 | 查询截图、资格不足的可理解提示 |
| 安全/回归 | 上传损坏 CSV、重复模型 ZIP、跨实例/篡改签名模型，观察明确拒绝；原数据库及模型未被改写 | 错误消息、前后文件校验、测试日志 |

## 4. 通过标准与未完成项

- Linux 中新功能专项与静态前端回归通过，详见 `docs/UPGRADE_STATUS_AND_NEXT_STEPS_20261105.md` 的测试记录；它们不等于 Windows GUI 验收。
- 旧全量测试仍受过时契约、缺示例介质、PyTorch 依赖和本环境浏览器沙箱等因素影响，**没有全量 PASS 证据**。现场应分别记录新功能通过情况和旧门禁失败原因。
- 无标签 CSV 的「只推理、输出分数、不计算准确率」已在本候选接入；跨实例的任意 `.pkl` / `.joblib` 模型不在可信导入范围，模型认证密钥不随源码迁移。
- 不能用任何源码包覆盖旧系统的 `datasets/`、`models/`、`outputs/` 或实例签名密钥；建议把功能试用作为独立安装先验收，再规划数据迁移或回退。

## 5. 回退

保留未改动的旧安装目录，备份每个使用中的 V2 主库、模拟库、模型、输出和配置。试用不满足时停止新目录服务，继续启动旧目录，不进行两套运行目录间的原位数据库混合或跨实例模型包反序列化。

## 2026-11-06 P3-B/C 增量验收

- 在历史库导入页面用时间列为 `采样时刻`、标签列为 `fault_state` 的 UTF-8/GB18030 多列 CSV 预览，检查缺失、无效数字、重复时间行号和帧号；忽略说明列，保存一个映射预设，重新打开后应用。
- 同名不同列集合不得自动套用旧预设；修改单位后旧预检凭证失效。
- 故障模拟 CSV 工作区显示同结构数据质量摘要，连续两次注入后重启读取，版本级质量信息保留。
- 在任务查询与导出页比较两个经归档验证且输入完全相同的有标签监督评估，检查并排准确率/F1 等数值；选择无标签推理或不同数据源时只显示不可比原因。
- 在新 Windows 环境执行 `Run-UpgradeTests.ps1`（Node.js 缺失会明确报告跳过），再跑原始 Smoke/Full；必须实际截图确认前端交互，不能用静态测试结果代替。


## 2026-11-06 P3-C 任务失败诊断与恢复增量

- 训练失败、评估失败、无标签仅推理失败以及报告归档待处理，均在运行页面显示结构化阶段、原因和恢复动作。
- 同步评估/仅推理的失败及归档关注状态现在写入安全任务状态文件，可在刷新和服务重启后从任务历史检索。持久化内容不包括请求配置、CSV/遥测样本或异常堆栈。
- 任务历史提供训练/评估/仅推理对应的返回入口。恢复操作是用户确认后创建新任务，不自动重放旧请求。
- 最新候选 ZIP 文件名和 SHA-256 以本次交付通知为准；ZIP 内的 `AAS/UPGRADE_SHA256_MANIFEST.json` 对全部源码文件逐项校验。请勿把源码包覆盖到已有 `datasets/`、`models/`、`outputs/` 或实例密钥目录。
