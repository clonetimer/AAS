# 实验输入证据与数据快照

AAS 从执行端记录实际输入，而不通过网页重新提交的数据生成可信记录。训练/评估运行时，`TrainingPipeline` 在以下两个时刻取证：

1. **raw**：过滤无效值、筛选时间窗口、同步多参量时间戳并完成训练/测试划分之后；
2. **model**：归一化之后、实际调用 detector 前。

每个阶段分别对有序的 `train` 和 `test` 样本计算 SHA-256，摘要包括特征顺序、每行实际输入向量、时间戳和标签；多参量还记录用于生成该行的各源参量观测时刻与来源标签。同步元信息及归一化参数也会计算摘要。因此，同一物理表但不同时间窗口、特征顺序、样本划分或归一化过程，将产生不同证据。

## 归档

新任务必须走受服务端保护的“执行 → 一次性凭证 → 保存历史”链路。历史任务 `reports/summary.json` 的 `provenance.effective_model_inputs` 记录输入摘要：

- `snapshot_status=complete`：同时保存 `reports/execution_inputs.json.gz`，包含两阶段 train/test **全部有效输入样本**，适用于小数据集。
- `snapshot_status=digest_only_size_limit`：完整流摘要仍存在，但超过归档上限，因此**不保存矩阵**；仅凭归档不能重建训练数据。这是明确的不完整快照状态。
- `snapshot_status=not_captured`：旧执行链或模拟测试没有输入证据，不能误称有完整输入快照。

为避免长时间任务和高维数据使服务器内存、磁盘无界增长，每阶段上限为 20,000 个有效输入行（训练和测试合计）及 4 MiB。超过上限不会保留一个看似完整的截断文件。

执行：

```bash
python scripts/verify_experiment.py outputs/experiment_<ID>/reports/summary.json
```

核验工具会对结果、完整配置、输入矩阵归档重新计算摘要，并对每个阶段及划分逐行验证。快照缺失或任一归档被篡改时会失败。此前未生成输入证据的旧任务仍可按旧规则核验其已有结果，不会补造矩阵。

## 科学性与安全边界

- 这里记录的是**本次观察到的真实输入值**，不是可重跑任何模型的充分条件。完整可复现还需固定随机种子、运行环境、算法与模型版本等。
- 完整输入快照可能包含敏感遥测数据，存储在服务端受管输出目录；不要在未审查数据内容和访问权限时向外共享。
- 摘要无法独立证明算法正确，也不等于外部数字签名；本机管理员仍可以同时篡改归档及摘要。
- 对于超限任务，仅有有序输入摘要、样本数量和特征次序，不等同于物理数据源快照。需要重算时应恢复原始数据及一致的预处理、时间同步环境。
- 当前不修改检测算法的阈值、报警逻辑或结果判决。
