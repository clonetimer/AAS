# AAS 用户快速入门

本手册面向首次使用 AAS 的用户。普通使用者不需要了解 Python、SQLite 或项目源码。

## 1. 安装和启动

1. 解压完整 Windows 离线包，保持包内目录结构。
2. 双击 `一键部署.cmd`，按提示完成安装。默认安装目录为当前 Windows 用户的本地应用数据目录下的 `AAS`；也可在命令行指定其他磁盘。
3. 安装完成后，双击安装目录中的 `Start-AAS.cmd`。
4. 浏览器打开本机 AAS 首页。
5. 首次使用时设置管理员账号和密码；之后使用该账号登录。

首次使用内置示例遥测建库时，需要较多磁盘空间。部署程序会在建库前检查空间；请以安装器显示的要求为准。安装目录、数据库目录和日志目录不要放在临时清理目录中。

## 2. 首页功能入口

| 功能 | 适用场景 |
| --- | --- |
| 历史遥测数据库 | 查询和管理长期保存的历史遥测数据 |
| 故障模拟数据库 | 导入独立 CSV，在指定帧区间叠加一种或多种故障 |
| 数据预处理 | 对历史参量或本地 CSV 进行清洗、滤波、差分和质量检查 |
| 算法训练与评估 | 使用历史数据或独立训练/测试 CSV 训练、发布和评估模型 |
| 实验结果与导出 | 查询任务状态、曲线、事件级指标和报告 |
| 检测算法管理 | 查看算法、参数配置和扩展 |
| 软件性能监控 | 查看本地服务、CPU、内存、磁盘和任务运行情况 |

## 3. 先理解三类数据区域

| 区域 | 数据保存位置 | 主要用途 |
| --- | --- | --- |
| 历史遥测库 | `datasets/aas_telemetry_v2.sqlite` | 长期保存、查询和管理历史遥测 |
| 故障模拟工作区 | 独立模拟工作区数据库 | 保留原始 CSV 和逐次注入版本 |
| 训练/测试用户 CSV 工作区 | `datasets/user_csv_workspaces/user_csv_workspace.sqlite` | 保存用户自己的训练和测试 CSV |

训练/测试 CSV 不会导入历史遥测库。它们会持久保存，供后续重复选择；用户可以在训练/评估页面主动删除。正在被任务引用的数据不能删除。

本地 CSV 预处理只生成可下载的处理结果，不自动保存到以上数据库。

## 4. 推荐的第一次使用流程

### 流程 A：快速查看历史数据

1. 打开「历史遥测数据库」。
2. 选择卫星型号、分系统、部件或参量。
3. 检查时间范围、数据质量和曲线。
4. 需要长期纳入管理的外部遥测文件，使用该页面的 CSV 导入向导。

### 流程 B：模拟故障

1. 打开「故障模拟数据库」。
2. 导入自己的 CSV。
3. 检查数值参量、帧顺序和原始数据。
4. 选择故障类型、参量和起止帧。
5. 保存注入版本；可在该版本上继续叠加其他故障。
6. 导出选定版本的完整 CSV。

模拟 CSV 不会进入历史遥测库。

### 流程 C：用自己的 CSV 训练和评估

1. 打开「算法训练与评估」。
2. 在训练区域导入 CSV，完成检查、字段映射和预检。
3. 确认后，文件保存到独立训练/测试工作区。
4. 在「我的 CSV 数据集」中选择文件，设置算法参数并启动训练。
5. 按评估结果和独立验证证据决定是否发布模型。
6. 在测试/评估区域导入测试 CSV，选择已发布模型并启动监督评估；没有真值的测试数据使用仅推理。
7. 打开「实验结果与导出」查看任务状态和结果。

不要把无标签测试数据标记为全正常。未知真值只能用于无标签推理，不能用于计算需要真实标签的监督指标。

## 5. 模型状态怎么理解

- **已保存**：模型文件已经保存，可在系统模型列表中查看。
- **已发布**：模型通过发布流程，允许作为正式评估模型使用。
- **实验模型/验证模型**：用于开发或对照实验，不应仅凭名称或单次指标作为正式诊断模型。

正式使用前，应检查模型对应的训练数据、参量、坐标模式、标签规则和独立评估结果。AAS 不会因为模型文件存在就自动认定模型有效。

## 6. 关闭、备份和卸载

- 正常关闭服务：双击安装目录中的 `Stop-AAS.cmd`。该操作会向本机服务发送受控停止请求。
- 备份：停止服务后，备份 `datasets/`、`models/` 和需要保留的配置文件。数据库备份应在服务停止后进行。
- 卸载：双击 `Uninstall-AAS.cmd`。默认保留用户数据并移动到同级备份目录；只有明确选择删除数据时才会删除数据库和模型。
- 不建议直接删除运行中的安装目录，也不要手工删除正在使用的 SQLite 数据库文件。

## 7. 遇到问题时

先查看安装目录中的 `logs/` 和部署日志，再到「任务查询与导出」查看任务失败阶段。不要通过删除数据库、模型或工作区文件来尝试修复问题。需要重新部署时，优先使用新的安装目录并保留原数据备份。
