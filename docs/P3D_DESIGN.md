# P3-D：大数据量操作与长任务体验设计

## 意图
统一管理 AAS V2 的导入、预处理、训练、监督评估和无标签仅推理任务。用户应能看到可信进度、切换页面后继续查询状态，并在安全边界允许时取消任务；服务重启后如实显示中断，不自动重放计算或写库操作。

## 目标
- 扩展现有 TaskRuntime，统一任务状态、进度、取消请求、终态持久化和历史查询。
- 复用 AlgorithmProcessService 子进程隔离，取消时终止算法 worker 进程树。
- 将监督评估和无标签仅推理改为后台任务，返回任务 ID。
- 将 Phase 48/49 磁盘流式批量导入接入统一任务生命周期；Phase 49 逐文件收据保留为领域明细，任务主状态映射到 TaskRuntime；取消仅在文件事务边界生效。
- 通用 CSV/CSV.GZ 导入使用磁盘暂存和流式解析，避免完整上传文件及解压内容同时驻留内存。
- 前端统一显示 queued/running/cancelling/completed/failed/cancelled/interrupted，并提供明确取消确认。

## 非目标
- 不引入 Redis、Celery、独立 Worker 服务或新的数据库服务。
- 不自动恢复或重放重启前任务。
- 不改变标签真值、训练/测试划分、模型输入契约、归档凭据或 SQLite 主 Schema。
- 不把浏览器关闭/XHR abort 等同于服务端取消。
- 不在模型发布、凭据签发、报告归档或 SQLite 文件事务中途强行中断。

## 方案与决策
采用方案 A：扩展现有 TaskRuntime 和 AlgorithmProcessService，保留当前 HTTP/SQLite 部署架构。Phase 49 文件级收据继续作为导入审计明细，主任务生命周期映射到 TaskRuntime；算法 worker 通过进程树终止取消；数据库导入在文件事务边界协作取消。方案 B（独立 Worker + 队列）资源隔离更强，但会增加离线安装、服务监控和维护复杂度，不符合当前交付优先级。

## 约束与验收
- 兼容 Windows 10/11 和离线 Python 部署，不新增必须在线下载的依赖。
- 只持久化任务状态投影，不保存 CSV、遥测矩阵、请求配置、模型对象、异常堆栈或一次性执行凭据。
- 取消请求显式确认且幂等；终态不可取消；不可取消阶段给出原因。
- 服务重启时 running/cancelling 变为 interrupted。
- 批量导入按单文件事务提交；已提交文件保留，当前文件事务完整提交或回滚。
- 任务状态和结果必须可跨页面查询；不得泄露私有路径或内部执行凭据。
