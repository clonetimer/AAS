# 第一次使用：CSV 导入四步向导

这份说明对应 **P3-G0-3 专项候选版，基于 P3-G0 v2**。四个入口都采用相同的四步操作：**检查文件 → 核对字段与用途 → 确认导入 → 使用结果**。每一步都有当前用途、数据去向和下一步提示。

## 1. 先选对入口

| 你准备做什么 | 打开哪里 | 导入后的去向 | 完成后点击什么 |
| --- | --- | --- | --- |
| 把遥测文件登记到历史库，并逐列指定属性 | 历史故障数据库 → 导入 CSV | 当前活动历史库的新来源；由你指定训练或测试用途 | 返回历史库筛选参量 |
| 保留完整原始表，之后添加模拟故障 | 模拟故障数据库 → 本地 CSV 工作区 | 独立模拟库的原始版本 v0 | 继续设置故障注入 |
| 用正常数据建立模型基线 | 算法评估 → 训练 → 导入 CSV | 历史库中的训练来源 | 检查训练时间范围 |
| 使用已经发布的模型检测数据 | 算法评估 → 测试/评估 → 导入 CSV | 历史库中的测试来源；真值未知时仅推理 | 选择模型并检查测试数据 |

历史、训练、测试共享活动历史库，但用途和准入规则分别校验；模拟 CSV 使用独立的模拟库。完成页按钮只帮助你到达下一步，训练、评估和故障注入都要另行启动。

## 2. 第一步：检查文件

选择文件，然后点击检查按钮。**选择文件本身不会上传文件。** 检查会读取真实列名、样例和质量信息，并识别编码与分隔符。

核对中文是否正常、列是否正确拆分、数值和时间是否落在预期列中，再勾选格式确认。只有确认后才能进入第二步。修改文件、编码或分隔符后，需要重新检查和确认。

历史库继续支持原有 CSV、CSV.GZ 和 SQLite/DB 表选择。SQLite 不需要 CSV 编码确认。原有各入口的文件大小与完整校验限制继续生效；页面显示的限制以对应入口为准。

## 3. 第二步：核对字段与用途

### 历史库、训练和测试

检查时间列、真实标签列、数值参量及单位。文本备注通常不应作为检测特征。历史库可以逐列编辑参量属性，或使用映射文件与本机预设。

填写能区分本次数据来源的运行标识。数值时间（如 `time_s=0,1,2`）是某次运行内的相对时间；填写对应的时间基准标识，不要把不同运行的相同秒数当作同一条时间轴。只有数据确实提供带时区的日期时间时，才选择相应 UTC 时间域。填写文件实际使用的时间单位和参量单位，不能根据数值大小猜测。

训练/测试快捷入口使用该入口提供的公共属性设置；如果同一文件的参量需要不同单位或不同属性，可使用历史库的逐列映射，并选择正确的训练/测试用途。

| 文件的标签情况 | 需要做什么 | 系统会如何使用 |
| --- | --- | --- |
| 有真实 0/1 标签 | 选对标签列，核对标签作用范围 | 保留源文件标签，仍按目标和来源规则校验 |
| 无标签，准备用于正常训练 | 独立确认所有训练样本确实正常，再勾选确认 | 才允许作为正常训练数据并写入标签 0 |
| 无标签，准备用于测试 | 确认真值未知 | 保存未知标签，后续仅展示异常分数与报警，不计算需要真值的指标 |

“无标签”不等于“全部正常”。运行级故障标签也不等于每个参量都发生故障。

点击“预检导入”。预检检查完整数据、字段和用途是否符合当前接口要求，不写入正式来源。通过后才进入第三步。

### 模拟库

核对文件样例、可注入的数值参量及质量提示。系统保留完整表，包括文本、原标签和原帧顺序；之后再选择要注入故障的参量和帧区间。

模拟入口的第三步摘要使用已有检查结果。点击“确认导入模拟库”时仍会执行完整校验并保存原始版本；不要把摘要当作已经写入的收据。

## 4. 第三步：确认导入

核对原文件名、保存位置、帧数、参量与标签含义，再点击对应的确认导入按钮。没有取得的统计值会显示为待完整校验，不会用 0 冒充检查结果。

修改文件会使文件检查失效；修改字段、用途、单位或标签确认会使预检失效。这样可以保证确认的是当前设置。

导入过程中，向导会锁定表单和步骤导航，并显示进度。取消按钮是否可用取决于当前服务端任务阶段。历史库会等待真实异步任务结果，收到“已受理”还不会显示导入完成。

## 5. 第四步：使用结果

出现完成页后，核对导入回执。训练/测试导入会尝试刷新并选中新来源；模拟导入会尝试刷新工作区。若数据显示已保存而后续刷新失败，按页面提示手动刷新和选择来源，避免再次导入同一份数据。

历史库弹窗会保留完成页，点击“返回历史库筛选参量”才关闭。训练和测试分别保留在自己的页面。下一步按钮不会自动训练、评估、仅推理或注入故障。

## 6. 常见问题怎么继续

| 遇到的问题 | 接下来做什么 |
| --- | --- |
| 中文乱码、列拆分不对 | 回到第一步，调整编码或分隔符，重新检查并确认 |
| 映射 CSV 表头错误或漏了参量 | 按提示完成源文件格式确认后进入第二步；替换正确映射，或点击“移除映射文件”后手动核对，再重新预检 |
| 映射文件中的型号或运行标识与表单不一致 | 核对真实来源身份，统一文件和表单中的声明，然后重新预检 |
| 质量或用途校验失败 | 按错误提示修正数据/字段；此前的表单内容会保留，失败不会自动重试写入 |
| 已保存，但列表没有刷新 | 手动刷新对应历史库或工作区，按文件名/来源查找，再继续下一步 |
| 历史库提示任务结果未确认 | 到任务查询与导出、导入记录中核对；当前页会阻止重复提交，先确认原任务状态 |

“导入另一个文件”会回到第一步并清除本次向导审批；新文件仍需重新检查。它不会删除已经导入的数据。

## 7. 开发验收复跑

正常使用 AAS 不需要 Node。以下命令用于开发验证，在项目根目录执行；Python 使用项目运行环境，Node 18 或更新版本仅用于 jsdom 测试。

```text
npm ci --ignore-scripts
npm test
node tests/telemetry_v2_import_async_task_ui.cjs
python LOCAL_TEST/run_csv_wizard_acceptance.py
```

最后一条命令建立临时应用副本、全新数据库和临时本地管理员，通过真实 HTTP 运行四入口导入，再检查数据库用途、标签与任务。结束后关闭临时服务并删除临时副本；JSON 报告保存在 `outputs/csv_wizard_acceptance/report.json`。

真实 HTTP 与 DOM 验证不等于实际浏览器视觉验收。本候选版尚未完成浏览器窄屏、原生键盘/读屏及 Windows 10/11 实机验收，完整验证结果见同目录的 G0-3 专项进度记录。
