# CSV 导入向导：先选入口，再确认数据去向

AAS 有三种不同的数据存储区域。**选择 CSV 导入入口时，先确认数据要用于什么工作，不要把所有 CSV 都导入历史数据库。**

## 1. 先选对入口

| 你准备做什么 | 打开哪里 | 导入后的去向 | 后续操作 |
| --- | --- | --- | --- |
| 把真实遥测文件纳入长期历史数据 | 历史故障数据库 → 导入 CSV | 活动历史 V2 数据库，登记为一个新来源 | 筛选参量、查看曲线、预处理或作为历史训练/测试来源 |
| 保留完整原始表并反复叠加模拟故障 | 故障模拟数据库 → 本地 CSV 故障模拟 | 独立模拟工作区，先保存原始版本 v0 | 选择参量和帧区间，逐次注入并导出版本 |
| 用自己的正常数据训练模型 | 算法评估 → 训练 → 导入 CSV | 独立用户 CSV 工作区，标记为 train | 选择「我的 CSV 数据集」，检查数据后启动训练 |
| 用自己的数据测试已发布模型 | 算法评估 → 测试/评估 → 导入 CSV | 同一独立用户 CSV 工作区，标记为 test | 选择模型和「我的 CSV 数据集」后启动评估或仅推理 |

**训练 CSV 和测试 CSV 不写入历史遥测数据库。** 两者在 `datasets/user_csv_workspaces/user_csv_workspace.sqlite` 中独立持久保存，与历史库、故障模拟工作区分开。训练和测试按用途分别管理，但共用这个用户 CSV 工作区文件。

本地 CSV 预处理是另一条不落库的流程：在「数据预处理 → 本地 CSV」中直接处理并下载结果，不会写入历史库或训练/测试工作区。

## 2. 四步导入向导

四个导入入口采用一致的操作顺序：**检查文件 → 核对字段与用途 → 预检 → 确认导入**。每一步都会显示当前用途和数据去向。

### 第一步：检查文件

1. 选择 CSV 文件。
2. 点击「检查文件」。
3. 核对编码、分隔符、列名、样例和质量摘要。
4. 确认文件格式后再进入下一步。

选择文件本身不会保存数据。更换文件、编码或分隔符后，需要重新检查。

### 第二步：核对字段与用途

**历史数据库入口**

- 核对时间列、标签列、数值参量和单位。
- 为新来源填写可识别的来源名称、型号和运行标识。
- 确认时间字段和单位来自真实数据，不要根据数值大小猜测。
- 逐列映射时，文本备注通常不应作为检测特征。

**训练 CSV 入口**

- 选择真实数值参量及单位。
- 有真实标签时核对标签列和标签语义。
- 无标签训练数据只有在确认所有样本确实正常后，才允许明确确认并作为正常训练数据。
- 训练 CSV 保存到独立用户 CSV 工作区，不会创建历史数据库来源。

**测试/评估 CSV 入口**

- 有真实 0/1 标签时，核对标签列和标签含义，供监督评估使用。
- 没有标签时，保持真值未知，后续走无标签推理；系统不会把未知标签当作正常标签，也不会计算需要真值的监督指标。
- 测试 CSV 保存到独立用户 CSV 工作区，不会创建历史数据库来源。

**故障模拟入口**

- 核对原始列、数值参量和帧顺序。
- 系统保留完整原始表，再在选定版本上叠加故障。
- 每次注入都会形成新的版本，后续可继续注入或导出指定版本。

“无标签”不等于“全部正常”。运行级故障标签也不等于每个参量都发生故障。

### 第三步：预检与确认导入

点击「预检」后，系统会检查完整数据、字段、标签和用途规则。预检本身不写入正式工作区。

通过后核对：
- 原文件名和文件大小；
- 行数/帧数、数值参量数量；
- 时间或帧坐标模式；
- 标签状态；
- 目标工作区。

确认无误后点击对应的「确认导入」按钮。导入过程中请勿重复提交同一文件。

### 第四步：检查导入回执

完成后核对数据集 ID、行数、参量数量和存储位置。

- 历史库：返回历史数据库页面，按来源名称筛选。
- 故障模拟：在模拟工作区选择原始版本，开始注入故障。
- 训练/测试 CSV：在对应页面的「我的 CSV 数据集」中确认文件已保存并被选中。
- 若保存成功但页面未自动选中，先刷新对应工作区并手动选择，不要再次导入同一文件。

完成页的「下一步」按钮只负责跳转，不会自动启动训练、评估、推理或故障注入。

## 3. 训练/测试 CSV 的保存、复用和删除

训练/测试 CSV 会在用户 CSV 工作区中持久保存，服务重启后仍可查看。系统保留上传的原始文件字节、SHA-256、用途、导入摘要和对应的逻辑参量数据。

在训练或评估页面：
1. 在「我的 CSV 数据集」中选择已保存文件。
2. 检查文件用途和导入摘要。
3. 选择训练策略或已发布模型。
4. 启动任务并在任务查询页面查看结果。

用户可通过「删除所选 CSV」主动删除不再需要的数据。若该 CSV 仍被运行任务引用，系统会阻止删除；任务引用结束或完成恢复后再试。删除训练/测试 CSV 不会删除历史数据库中的数据，因为这些 CSV 本来就没有写入历史数据库。

## 4. 常见问题

| 遇到的问题 | 处理方法 |
| --- | --- |
| 中文乱码或列拆分错误 | 返回第一步，调整编码或分隔符，重新检查并确认 |
| 无时间列 CSV | 检查是否有显式 frame 列；若按行序作为帧号，必须确认原始行序含义 |
| 无标签测试数据 | 保持未知真值，使用仅推理，不要确认成全正常 |
| 训练 CSV 没有出现在历史库 | 这是预期行为；请到训练页「我的 CSV 数据集」选择 |
| 保存成功但没有自动选中 | 刷新对应页面，在「我的 CSV 数据集」中手动选择 |
| 删除提示任务仍在使用 | 到任务查询页面确认引用任务已经结束，再重新删除 |
| 导入失败 | 按页面提示修正字段、标签或单位；确认任务状态后再重试 |

## 5. 开发验收复跑

普通使用不需要 Node。开发验证在项目根目录执行：

```text
npm ci --ignore-scripts
npm test
node tests/telemetry_v2_import_async_task_ui.cjs
python LOCAL_TEST/run_csv_wizard_acceptance.py
```

真实 HTTP 与 DOM 验证不等于实际浏览器视觉验收。Windows 10/11 的完整离线安装仍需在目标机器完成端到端验收。
