# AAS V2 P1-B：训练 / 评估页面 CSV 导入与可信模型包

日期：2026-11-05；本地功能分支 `feat/aas-v2-ux-upgrade`。

## 用户操作

### 训练时导入本地 CSV

1. 进入「智能检测算法评估」的训练页面，展开「从本地 CSV 导入训练数据」。
2. 选择 `.csv` 文件，先点击检查文件；系统展示可用数值参量以及字段概览。
3. 选择需要参与训练的数值列，并设置卫星型号、分系统、部件等身份映射；明确选为「训练」用途。
4. 没有真实标签时，仅在**确实知道文件全为正常样本**的情况下，主动确认按正常训练样本导入。不要将未知标签当成正常事实。
5. 确认提交后自动刷新当前可选训练来源并选择新增来源；仍需完成正常的训练参数选择与运行。

### 评估时导入本地 CSV

1. 进入评估页面，展开「从本地 CSV 导入评估数据」，预检、选择数值列和映射后按「测试」用途提交。
2. 有真实 0/1 标签的 CSV 可以进入原有 V2 有监督评估；无标签文件仍保持真实标签未知，但可在模型特征契约一致时运行 **score-only 仅推理**。导入后界面自动切换「开始仅推理（无真值）」；结果只展示真实输入曲线、检测器给出的异常分数、阈值和报警，监督指标留空。
3. 导入后的 CSV 成为当前 V2 遥测主库中一个新的**逻辑数据来源**，不会覆盖原有采样。CSV 模拟工作区仍保存在独立模拟库中，两者入口和持久化目标不同。

### 评估时导入模型包

1. 已在本安装实例训练并登记的模型，可使用页面「导出 AAS 模型包」得到带认证信息的 `.aas.zip` 文件。
2. 在同一安装实例的评估页面上传该模型包，输入新模型显示名，确认导入。
3. 服务端先严格检查 ZIP 条目、大小、文件 SHA-256 和本安装实例的 HMAC 签名，之后才通过现有原生模型校验器恢复和登记新模型。
4. 直接上传任意来源 `.pkl`、`.joblib`、`.py` 或普通 ZIP 一律拒绝。本轮没有实现任意跨机器模型迁移。后续如需跨机器，应设计带独立用户授权、受控信任根与算法版本兼容检查的迁移流程。

认证密钥创建在运行时 `configs/aas_model_bundle.key`，绝不纳入交付源码压缩包和版本库；不要把它视为可公开分发的签名证书。

## 格式与限制

- 文件直接通过原有 V2 导入服务处理，支持 `.csv`，与既有 `.csv.gz` 流程一致地预检 / 预览 / 提交。CSV 列筛选仅选入被指定的数值参量。
- 训练和测试来源除了来源 ID 外还按原始文件摘要约束，避免同一文件改名后被当作独立训练与测试集。
- AAS 模型包上传限制 75 MB，未压缩模型内容限制 64 MB；只允许本安装实例签发且具有完整 V2 训练契约的原生模型产物。
- 样本不对齐、分组、时间先后、标签证据及归一化等仍由已有 V2 训练 / 评估约束控制，CSV 入口不会绕过质量检查。
- 无标签仅推理一次只允许一个用户明确导入的测试 CSV；必须使用列定义绑定、已发布的 V2 模型和训练期归一化契约。可以通过完整物理身份（分系统/部件/参量/单位）匹配训练数据和 CSV 的不同显示字段名，严格保持模型列序；模型筛选使用当前所选来源的单位而非全局名称目录。会阻止同训练组、同原始文件摘要及与训练来源存在重复完整采样帧的 CSV；训练来源缺失、原始摘要不符或物理语义不一致时拒绝执行。内容重叠检查不能替代外部来源独立性证明。未知真值绝不会推定成正常样本。生成的报告标记 `score_only`，监督 `metrics={}`，并在容量允许时归档原始及实际模型输入快照；未执行数据库物理表前后复核时明确记录变化状态未知。
