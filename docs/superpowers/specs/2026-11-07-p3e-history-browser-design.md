# P3-E：历史数据库大数据浏览设计

## 意图

让非程序员在较大的 V2 遥测数据库中稳定浏览参量目录、时间序列和采样明细。数据库规模增长时，页面不能一次性加载全部参量或全部采样；用户缩放/框选曲线后，服务端必须按选定时间窗口重新读取数据。

## 目标

- 参量目录采用服务端分页，筛选和排序保持确定性，筛选条件变化时回到第一页。
- 曲线初始概览覆盖所选时间范围，而不是只显示最早的前 N 帧；概览点数有硬上限，并尽量保留每个时间桶的首末点、数值极值和故障标签点。
- 滚轮缩放、按钮缩放和拖动框选都向服务端请求新的时间窗口；请求竞态不能用旧响应覆盖新视图。
- 增加单参量采样明细分页；不把不同参量按时间或行号强行拼成宽表。
- 明确区分逻辑帧数、有效数值样本数、绘图点数、重复物理记录数和明细页行数。
- 保留当前只读查询、角色隔离、时间域隔离、重复采样冲突拒绝和完整 CSV 导出语义。

## 非目标

- 不修改遥测数据、标签、来源用途、分片治理或模型训练数据。
- 不新增数据库 Schema、后台索引任务、缓存服务、Redis、Celery 或运行依赖。
- 不把多个部件/参量的不同采样时钟对齐成统一表格。
- 不改变全量 CSV 导出；曲线预览上限不限制导出。
- 不将客户端 SVG 缩放继续作为唯一缩放机制。

## 方案比较与决策

### 方案 A（采用）：SQLite 服务端分页 + 有界概览 + 时间窗重查

扩展现有 V2 查询接口。参量目录使用 SQL `LIMIT/OFFSET` 分页，筛选项通过 DISTINCT 查询获得；曲线概览在 SQLite 端按时间序列分桶，返回每桶的首末点、最小/最大值和一个故障标签代表点；缩放/框选把新的时间范围发回现有只读查询接口。采样明细按单个 channel 的稳定时间游标分页。

优点：复用现有 SQLite 索引和 V2 权限/用途约束，无 Schema 迁移，离线 Windows 部署不增加依赖。代价：概览查询仍需扫描所选时间范围的索引记录，超大数据库的查询耗时需用压力测试验证。

### 方案 B：预计算多级曲线瓦片

在导入/后台任务中生成多分辨率 min/max 图表瓦片。交互读取更快，但需要新增 Schema、旧库回填、导入/治理变更后的缓存失效与迁移验收，当前阶段成本和风险较高。

### 方案 C：浏览器分页拉取原始数据并本地抽稀

后端改动少，但大量 HTTP 请求和浏览器内存会随数据规模增长；刷新、缩放和网络中断时更难保证体验，不符合大数据量浏览目标。

## 数据口径

- `frame_count`：当前筛选条件下按逻辑时间键去重后的帧数；相同时间戳的完全相同重复记录只计一帧。
- `valid_sample_count`：上述逻辑帧中 `value_num IS NOT NULL` 的数量。
- `plot_point_count`：实际返回给曲线渲染器的点数；概览模式不得超过请求上限。
- `duplicate_count`：重复的物理采样记录数，即物理匹配行数减逻辑帧数。
- `page_row_count`：采样明细当前页实际返回的逻辑帧行数。
- 同一时间键出现不同数值或标签时，仍拒绝绘图/分页，不静默择一。

## API 与界面约束

- `GET /api/v2/telemetry/series/search` 接受 `limit`、`offset`，返回 `count`（总匹配数）、`has_more`、`next_offset`。
- `GET /api/v2/telemetry/filter-options` 不再通过加载完整参量对象构造 facets；改用数据库端 DISTINCT 查询。
- `POST /api/v2/telemetry/query` 支持 `mode=overview|page`。overview 使用 `start/end` 时间窗和有界抽稀；page 只允许一个 channel，使用稳定时间游标及 1–200 行页大小。
- 初始概览保留全范围时间边界；缩放/框选查询新窗口；重置恢复原始选择范围。
- 明细表只显示一个参量的采样记录，明确展示逻辑帧、时间、数值、标签、来源分片和源文件帧序号。
- 浏览器超时/切换筛选条件时，旧查询响应不得覆盖新结果。

## 验收

- 参量目录分页在筛选、排序、末页、空结果和边界参数下正确。
- 50,000+ 帧概览覆盖全时间范围，绘图点数受限，峰值与故障标签代表点保留。
- 放大/框选后服务端返回严格位于所选时间窗的数据；缩小和重置可恢复原窗口。
- 采样明细游标翻页无重无漏，重复数据去重，冲突数据拒绝。
- frame_count、valid_sample_count、plot_point_count、duplicate_count 口径在 API 和 UI 一致。
- 角色隔离、不同时间域拒绝混合、只读数据库和全量导出回归不退化。
- Linux 自动化回归通过；Windows 10/11 验收仍由 P3-H 完成，不在本阶段提前宣称。
