# P3-D：大数据量操作与长任务体验设计

## 意图

面向 AAS V2 的日常用户，统一管理长时间运行的导入、预处理、训练、监督评估和无标签仅推理任务。用户在等待期间应能看到可信进度、切换页面后继续查询状态，并在安全边界允许时取消任务；服务重启后必须如实显示中断状态，不自动重放计算或写库操作。

## 目标

- 扩展现有 `TaskRuntime`，建立统一任务状态、进度、取消请求、终态持久化和历史查询能力。
- 复用 `AlgorithmProcessService` 的子进程隔离，支持取消时终止算法 worker 进程树。
- 将监督评估和无标签仅推理改为后台任务，返回任务 ID；训练保持现有后台任务模型。
- 将 Phase 48/49 的磁盘流式批量导入接入可取消任务生命周期；取消只能在文件事务边界生效，当前文件提交/回滚完成后停止。
- 对通用 CSV/CSV.GZ 导入使用磁盘暂存和流式解析，避免将完整上传文件及解压内容同时保留在内存中；保留现有格式确认、标签语义、映射校验和事务约束。
- 前端统一显示排队/运行/取消中/完成/失败/已取消/服务中断状态，并提供明确的取消确认。

## 非目标

- 不引入 Redis、Celery、独立 Worker 服务或新的数据库服务。
- 不自动恢复或重放重启前的训练、评估、推理或数据库写任务。
- 不改变现有遥测标签真值、训练/测试划分、模型输入契约、实验归档凭据或 SQLite 主 Schema。
- 不把浏览器关闭、XHR abort 等同于服务端任务取消。
- 不在不可逆的模型发布、来源凭据签发、实验报告归档或 SQLite 文件提交中途强行中断。

## 约束

- 兼容 Windows 10/11 和现有离线 Python 部署；不增加必须在线下载的运行时依赖。
- 继续使用当前 `ThreadingHTTPServer`、`HttpApplicationContext`、`TaskRuntime`、`AlgorithmProcessService` 与 SQLite。
- 持久化只保存任务状态投影；不保存原始 CSV、遥测矩阵、请求配置、模型对象、异常堆栈或一次性执行凭据。
- 任务 ID 继续使用 32 位十六进制 UUID；任务状态写入采用临时文件 + 原子替换。
- 取消请求必须有明确确认；重复取消幂等；终态任务不可取消；不可取消阶段返回明确原因。
- 取消终态为 `cancelled`；服务重启时 `running` / `cancelling` 统一恢复为 `interrupted`。
- 批量导入按单文件事务提交；取消在文件边界生效，不回滚已提交文件。

## 方案比较

### A. 扩展现有运行时（采用）

在 `TaskRuntime` 中增加任务类型、取消事件、可取消阶段和安全状态投影；在 `AlgorithmProcessService` 中轮询取消信号并终止子进程树；导入任务在文件边界检查取消信号。评估和推理复用现有算法 supervisor，改为后台任务。

优点：不增加部署依赖；复用当前任务持久化、进程隔离和批量导入实现；Windows 离线部署复杂度最低。代价：后台线程仍由 Web 服务进程托管，重启时任务标记中断，不提供计算续跑。

### B. 独立 Worker 服务与持久化队列

增加独立进程、队列和服务管理机制。

优点：Web 请求与长任务资源隔离更强。代价：需要增加服务安装、启动、监控、升级和故障恢复流程，不符合当前离线交付优先级。

## 决策

采用 A。任务主状态统一由 `TaskRuntime` 管理；Phase 49 文件级收据继续作为导入审计明细；子进程负责可强制终止的算法计算；SQLite 导入只在文件事务边界检查取消；前端通过任务 ID 轮询服务端状态。不可取消阶段必须在 API 与 UI 同时明确告知用户。

## 验收标准

- 训练、评估、无标签推理及批量导入均可通过任务 ID 查询；刷新或切换页面不丢失状态。
- 允许取消的算法任务在规定时间内终止 worker 进程树，状态落为 `cancelled`，不留下伪造的成功结果或未发布模型。
- 取消与任务完成并发时只产生一个合法终态；终态不可被后续取消覆盖。
- 不可取消阶段拒绝取消并说明原因；批量导入取消不会破坏已提交文件或当前文件事务。
- CSV/CSV.GZ 导入采用磁盘暂存与分块处理；超限、损坏、编码错误、重复时间戳和取消均不产生半成品正式记录。
- 持久化与公开 API 不泄露请求配置、原始数据、绝对路径、异常堆栈和执行凭据。
- 既有训练、评估、导入、报告归档和 Windows 兼容性测试不发生非预期回归。
