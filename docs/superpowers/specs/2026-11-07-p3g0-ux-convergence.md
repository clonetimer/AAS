# P3-G0 用户交互体验收敛规格

日期：2026-11-07
分支：feat/aas-p3g-ux-convergence
基线：P3-E 文档分支 43359f809441e731ae66154b8b7e48b3694c01f5

## 本阶段目标

降低非程序员完成一次完整算法评估所需的认知负担和页面往返次数。保留现有后端数据隔离、任务生命周期、故障模拟版本和实验审计规则；本阶段优先做导航与状态连续性，不重写算法内核。

## 实施顺序

### G0-1 首页和导航收敛
- 首页仅保留一个“历史故障数据库”入口，删除与之功能重复的“遥测数据”快捷入口。
- 导航按“数据准备、故障模拟、算法训练评估、结果与任务、系统管理”分组。
- 不删除原有页面路由；旧链接可继续访问。
- 首页任务统计必须明确数据范围，优先读取持久化任务历史；若接口失败，显示“暂不可用”，不能用当前进程计数冒充总历史。

### G0-2 任务流程向导
- 增加“开始一次算法评估”主入口。
- 步骤：选择数据 → 数据检查 →（可选）故障模拟 → 训练或选择模型 → 监督评估/无标签推理 → 结果查看。
- 每一步展示所需输入、检查状态、下一步动作和返回入口。
- 向导只组织现有能力，不复制一套新的导入、训练或评估实现。
- 无标签数据不得进入监督指标比较；缺少必要来源或单位信息时阻止继续并说明原因。

### G0-3 统一 CSV 导入体验
- 共用前端向导外壳：选择文件 → 解析预检 → 字段映射 → 确认导入 → 导入结果。
- 用途选择决定后续字段和目标库：历史库、模拟工作区、训练来源、测试来源。
- 各用途仍调用现有独立 API 和后端校验；不得把不同用途合并到同一张逻辑表。
- 记住用户确认过的列映射预设，但只有列名/类型/单位契约匹配才允许套用；文件变化必须重新预检。
- 上传/解析错误应指出行号、列名和可采取的修正动作。

### G0-4 故障参数上下文解释
- 故障类型改变时，参数标签、单位、范围、默认值、影响说明和预览同步改变。
- 明确区分偏置量、漂移终值、固定目标值、尖峰幅值。
- 注入区间统一使用从 1 开始的闭区间帧号；说明结束帧包含在注入范围内。
- 说明各模拟模式支持的故障类型差异，不把 CSV 工作区和历史模式伪装成完全相同能力。

### G0-5 页面状态连续性
- 为可恢复筛选条件建立版本化、白名单化的页面状态模型。
- 至少保留参量/时间范围/数据来源/选中模型/算法参数草稿；禁止持久化原始 CSV 内容、遥测矩阵、模型对象、密钥或异常堆栈。
- 切换页面返回时恢复未提交草稿；已提交任务始终从持久化任务状态读取。
- 离开有未提交修改的页面时提醒用户；明确取消离开与保存草稿两种行为。
- 由实验报告跳回任务配置时，仅恢复允许恢复的字段，并再次执行服务端预检。

### G0-6 首页与任务中心统计口径
- 区分运行中、已完成、失败、已取消、服务重启中断、报告待处理。
- 明确统计时间范围和来源；首页计数与任务中心同口径。
- 报告待处理属于计算完成后的关注状态，不得重复计入失败。
- 无法读取持久化任务历史时展示降级状态，不显示伪造的 0。

## 非目标
- 不新增独立功能菜单或新的后台任务服务。
- 不更改历史遥测库结构、训练算法、故障注入数学定义和模型格式。
- 不改变报警后处理职责；AAS 记录算法输出和客观事件级指标。
- 不在本阶段宣称 Windows 验收通过。

## 验收方法
1. 无开发人员协助的首次用户可从首页完成导入、预检、训练、评估并找到报告。
2. 相同数据用途的 CSV 导入步骤一致；不同用途仍保持后端隔离。
3. 每一种故障类型都显示准确的参数定义、单位、区间和示例。
4. 页面切换/刷新后恢复安全的筛选条件和草稿；不会恢复已过期预检结果。
5. 首页任务统计与任务中心一致，服务重启后的任务状态正确。
6. 键盘可操作、错误提示可读、空状态和加载状态明确。
7. 新增 Node 浏览器契约测试、相关 Python API 回归通过；旧基线失败单独记录。
8. 完整源码包逐文件 SHA-256/ZIP CRC 通过；Windows 现场验收仍归 P3-H。
