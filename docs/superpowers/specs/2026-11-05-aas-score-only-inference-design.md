# AAS V2 无标签 CSV 仅推理闭环（设计）

## 用户意图与现状

评估页允许导入无标签 CSV，但 V2 数据目录和评分流程均强制使用 0/1 真值，导致用户导入成功却无法继续。这不是数据损坏，而是监督评估与无真值推理被混在同一入口。目标：非程序员可选择已经发布的兼容模型，对本地未知真值测试 CSV 做一次实际推理，查看异常分数、算法自身判定与可追溯报告。

## 方案权衡

1. **独立 `inference/run` API + 同一评估页面的模式提示（选用）**：仅推理独立调用已加载模型，继承严格模型参量/归一化/来源隔离，避免对已验证的监督计算引入可选空标签。少量增加模型评分逻辑，但原监督评估不变。
2. 在现有 `evaluation/run` 中透传 `score_only`：路由更少，但需要修改 `DataLoader` 的标签假设、`TrainingPipeline` 指标引擎、报告定义，回归风险较大。
3. 把未知标签临时设为 0：会生成错误的准确率及故障对照，明确放弃。

## 必备行为

- 只接受**已明确作为 test 用途**且所有标签为 SQL NULL 的 V2 CSV 来源；不能因缺标签而视为正常，更不能混入训练集。
- 支持 **单个来源**、模型固定的有序参量列表与明确 numeric `time_s` 秒基准；读取有界、按运行时间排序、无效数值过滤/记录；同组或相同源数据摘要不能与训练源重叠。
- 使用已发布模型的保存目录和训练期 scaler 参数。独立工作进程仍受超时和并发约束；模型只调用 `score`/`detect`，绝不调用 `fit`，阈值/报警决策由算法自己负责。
- 返回 `evaluation_mode=score_only`、每帧 `score`/`pred_label`（算法不提供时留空）、明确 `ground_truth_available=false`，**不生成 accuracy、precision、recall、F1、延迟等监督指标**。
- 不在前端伪造模型执行结果；由服务器登记执行与来源证据并归档为不计指标的评估子类型；重启后报表可查询，普通有标签评估保持旧流程。
- 页面仍在「智能检测算法评估」：导入无标签 CSV 后自动选中评分来源及兼容模型，按钮及提示切换为「仅推理（无真实标签）」，绘图不显示伪真值红背景；有标签测试保持原文案与评价流程。

## 非目标和约束

- 不实现任意 `.pkl` / `.joblib` 文件直接加载；只允许同实例发布/认证模型。
- 不自动推断故障类型或评估正确率，不进行统一报警后处理。
- 不引入新的 Python/JS 大依赖；适配现有 Windows 10/11/PowerShell 5.1 入口。
- 旧全量测试受基线依赖和退役接口影响；新功能必须专项全绿，不能据此宣称 Stable。

## 验收路径

「导入 16 帧无标签测试 CSV → 选择已有模型 → 仅推理 → 曲线/分数/报警 → 报表列表重开找到任务」，且同文件改名不能与训练数据混淆。缺模型/缺列/错误单位/组重复/签名篡改/样本时间倒退都应给出可理解错误。原已标注测试运行仍能计算客观指标。
