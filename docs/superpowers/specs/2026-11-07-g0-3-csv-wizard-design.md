# P3-G0-3：统一 CSV 导入向导

## 目标与授权

按用户明确要求直接实施 G0-3。首次使用者在历史库、模拟库、训练、测试四处均能看清当前步骤、操作原因、写入位置与完成后的下一步。基线是经过整包和 649 项文件哈希核验的 P3-G0 v2；原始 ZIP 保留。

## 实现选择

采用共享的原生 JavaScript 分步组件，连接三个既有导入适配器和四个界面实例。组件负责阶段展示、导航、核对摘要、状态与焦点；现有适配器负责文件解析、请求、校验和写入。直接合并后端会改变用途边界；仅增加步骤说明不能降低一次展示的控件数量，因此本轮把实际表单按步骤展示。

四步为：**检查文件 → 核对字段与用途 → 确认导入 → 使用结果**。阶段导航只切换界面；检查、预检、写入都由用户点击明确命名的操作按钮触发。

## 行为与约束

- 文件检查和格式确认成功后才可进入字段步骤。修改文件/编码/分隔符使检查与预检失效；修改映射、用途或标签确认使预检失效。
- 历史、训练、测试仍走 `/api/v2/telemetry/import-source`；模拟仍走 `/api/v2/csv-workspace`。训练/测试身份、标签语义、摘要绑定、资源限制、事务、取消及服务端校验保持原协议。
- 历史、训练、测试的第三步只在预检成功后开放。模拟已有完整检查接口，第二步核对全部保留列、可注入数值列及质量信息，第三步明确最终导入仍完整校验，不伪装成新增的后端预检。
- 核对摘要显示原文件名、数据用途及目的地、帧数、参量数/列名、时间/标签语义。未知标签明确引导到仅推理；训练无标签仍要求用户确认全部正常。
- 导入成功与后续选中/刷新成功分开表达。已写入但刷新失败时保留完成凭据，提示手动刷新，避免引导重复导入。
- 请求期间锁定向导表单和步骤导航，保留外部进度及取消入口。失败保留输入，给出可操作恢复方向；错误通过可访问状态区报告。
- 完成后提供明确导航：历史库返回浏览；模拟定位故障注入；训练/测试定位已选来源和时间范围。导航不启动算法。历史弹窗在用户选择返回时关闭。
- 保留原元素 ID、路由、SQLite 导入、映射预设、批量导入、训练与故障版本链功能。高级身份字段按需展开。
- 使用语义化 fieldset/legend、真实按钮、aria-current、可见焦点和窄屏布局；所有业务依赖仍是原来的 Python/浏览器运行时，Node/jsdom 仅用于开发测试。

## 验证与交付

执行真实 DOM 行为测试，覆盖四入口、错误回退、旧审批失效、并发防护、未知标签和下一步导航；执行现有 CSV/质量/用途隔离和 UI 回归。在独立测试库进行真实浏览器操作、窄屏与键盘验证。记录已验与未验范围；P3-H Windows 实机验收不在本轮宣称完成。

公开 GitHub 分支继续只保存进度记录；完整源码以新的候选包交付，不覆盖 P3-G0 v2。
