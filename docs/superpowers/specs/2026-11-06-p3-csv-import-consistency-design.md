# P3-A：CSV 导入格式一致性设计

日期：2026-11-06  
基线：`AAS_V2_upgrade_20261105_score_only_candidate.zip`，Phase 53 R7 Candidate / R3.9。  
状态：按用户“按照顺序继续推进”授权实施；本设计不代表 Windows 实机验收。

## 意图

让模拟故障工作区、历史遥测数据库导入、训练/评估 CSV 入口使用一致的编码与分隔符识别规则，减少现场 Excel 导出文件因 GB18030、分号或 TAB 被误读而失败的情况。格式检查必须先于预检和写库，原始文件摘要必须基于上传的原始字节。

## 当前实现与根因

- 训练/评估页面 `runner-csv-import.js` 已通过 `/api/v2/telemetry/import-source` 支持 UTF-8（含 BOM）、GB18030、逗号/分号/TAB，并要求用户显式确认格式。
- 历史数据库导入后端 `telemetry_v2_source_import.py` 已支持相同格式，但 `telemetry-v2-import.js` 对普通 `.csv` 仍使用浏览器 `file.text()` 和本地逗号解析，绕过后端检测；CSV.GZ/SQLite 才走二进制接口。
- 模拟 CSV 工作区 `v2_csv_workspace.py` 仅接受 UTF-8、逗号分隔 `.csv`，页面没有格式确认；与训练/评估入口不一致。
- 模拟工作区数据以不可变版本写入独立模拟数据库，历史主库不得被本次导入改写。
- 结果报表已有输入可比性检查接口和基础 UI；该项不是本阶段重建目标，后续 P3-C 再改善比较呈现与失败原因解释。

## 目标

1. 模拟工作区与历史数据库导入都支持 UTF-8（含 BOM）/GB18030，以及逗号、分号、TAB。
2. 模拟工作区支持 `.csv` 与 `.csv.gz`；保留当前 8 MB 上传上限、50,000 帧上限和 12 MB 解压上限，不在本阶段放宽资源约束。
3. 首次检查自动建议格式；用户可以手动调整后重新检查；未勾选格式确认不得预检或写库。
4. 文件、编码或分隔符变化时，旧检查和预检授权失效；只调整列映射不强制重新上传文件。
5. 检查阶段只读，不创建或修改数据库；导入时重新解析同一原始字节，并保留原始 SHA-256。
6. 继续注入历史模拟记录的内部流程显式传递 UTF-8/逗号确认，不能被新确认门禁破坏。

## 非目标

- 本阶段不扩展历史库或模拟库的最大文件、帧数限制。
- 不在本阶段完成全量数据质量报告、逐行错误表格、列角色模板；列入 P3-B。
- 不在本阶段重做实验比较；现有比较 API 保留，P3-C 评估其用户体验。
- 不把未知标签自动赋值为正常，不修改主历史数据库，不更改故障注入数值算法。

## 实现路径与取舍

- 方案 A：在模拟工作区复制一套格式解析逻辑。改动小，但未来训练、历史导入和模拟会再次分叉，拒绝。
- 方案 B：把现有 `telemetry_v2_source_import.py` 全部重构成公共导入框架。长期整洁，但本阶段改动面过大，增加回归风险。
- **方案 C（采用）：抽取轻量 `csv_format.py` 公共解析原语，保留历史导入现有函数签名作为兼容包装；模拟工作区调用同一公共解析器。** 既统一编码/分隔符/压缩边界，又不重构业务导入管线。

## 交互约定

两处导入均采用同一流程：

`选择文件 → 自动识别格式 → 显示建议 → 用户确认或修改后重新检查 → 列映射/字段检查 → 预检 → 确认导入`

- 格式控件：编码（自动识别、UTF-8、GB18030/GBK）和分隔符（自动识别、逗号、分号、TAB）。
- 格式变化使检查结果失效；必须重新检查并再次确认。
- 导入状态区展示检测结果、文件大小/解压大小、原始 SHA-256、行/帧数和错误提示。
- 超出资源限制或格式错误时，指出具体限制或首个错误行；不静默截断、不部分写入。

## 数据与接口约定

- 公共模块提供有界 GZIP 解压、严格编码解码、分隔符检测、分隔符标准化。
- 模拟工作区 `inspect_csv(raw, filename, *, csv_encoding='auto', csv_delimiter='auto')` 只读返回解析建议；`import_csv(..., *, csv_encoding, csv_delimiter, format_confirmed)` 必须收到显式格式与确认。
- 模拟工作区持久化 `csv_encoding`、`csv_delimiter`、压缩类型及原始字节 SHA-256；派生版本继承格式元数据。
- HTTP 二进制接口使用 Base64 JSON 格式元数据头，原始文件字节作为请求体；服务端白名单校验元数据字段。
- 历史导入 `.csv`、`.csv.gz`、SQLite 均走现有二进制只读导入路由；CSV/CSV.GZ 的 preview 与 commit 使用完全相同的编码/分隔符。

## 验收标准

- GB18030 + 分号 + 引号内分号；UTF-8 BOM + TAB；GB18030 + TAB 的 CSV.GZ 均能正确检查和导入。
- 未确认、自动选项未解析、格式变化后沿用旧检查、预检与提交格式不一致均被拒绝。
- 原始 SHA-256 等于原始上传字节摘要；导出数据值、帧数和列名不因格式标准化而改变。
- 模拟版本链、历史主库隔离、训练/测试标签门禁和内部“继续注入”流程不回退。
- 对应 Python 与浏览器脚本测试通过；完整候选专项回归如实记录；Windows GUI 仍需现场验收。
