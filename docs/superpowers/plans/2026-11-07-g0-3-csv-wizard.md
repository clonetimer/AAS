# G0-3 CSV Import Wizard Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans for implementation, with independent read-only audits and a fresh final code review.

**Goal:** Deliver one understandable four-step CSV import experience across all four existing entry points.

**Architecture:** A shared UI component displays existing controls by stage. Three existing adapters supply verified state, summaries and completion actions; business endpoints remain separate.

**Tech Stack:** Python HTTP service, native browser JavaScript/CSS/HTML; Node test runner and jsdom for development tests.

**Spec:** `docs/superpowers/specs/2026-11-07-g0-3-csv-wizard-design.md`

## Global Constraints

- Preserve backend data-purpose isolation, original labels and unknown-truth score-only behavior.
- Preserve element IDs, routes, file-size limits, transactions and cancellation.
- Original candidate archive remains unchanged. Public repository receives progress documentation only.
- User explicitly authorized direct implementation; routine UI decisions are resolved in this plan without a further approval round.

## Review Focus

- File or mapping edits after preview revoke readiness; stale async responses never reopen approval.
- A completed import followed by a refresh error stays imported and never invites a duplicate write.
- History import in an iframe completes visibly and returns to the parent browser only on request.
- Native form validation must work when other fieldsets are hidden; required fields must be focusable when validated.
- Narrow layouts, keyboard navigation and long filenames keep the current action visible.
