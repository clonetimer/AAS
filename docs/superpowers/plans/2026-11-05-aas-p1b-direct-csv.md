# P1-B 第一阶段：训练/评估页直达 CSV 导入

采用已存在的 V2 原生导入、训练和评估内核，不引入纯 Python 替代检测器，不读取外部 pickle。

## Task 1 — 原生导入支持直接上传 .csv

- 扩展 `telemetry_v2_source_import` 的 `source_operation`，让 `.csv`、`.csv.gz` 共享 `inspect/preview/commit` 的安全映射及实际 SHA-256；原始历史主库绝不被覆写，导入前必须明确数据用途。
- 测试正常训练 CSV、带标签评估 CSV、无标签测试的显式确认；非法名称、错误映射拒绝。
- RED→GREEN、提交。

## Task 2 — 训练/评估界面内直接上传与映射

- 训练和评估工作区增加 CSV 抽屉；选择文件、映射型号/分系统/部件/单位、预检及确认导入；目标为当前活动 V2 库中**新**的逻辑来源，不改已有采样。
- CSV 无真实标签时训练必须用户主动声明全部正常；评估按未知标签导入，指标以标签证据为准。
- 导入成功刷新 V2 运行清单并自动选中新增 source_id（允许手动调整）。测试 UI 与后端 HTTP。
- RED→GREEN、提交。

- 明确允许的格式和信任边界：模型加载可能涉及反序列化；不得直接执行任意上传 pickle/joblib/py。
- 仅限经本安装实例认证、含全部模型元件的 AAS 模型包；先提供导出/导入验签、路径隔离及失败提示，并更新模型清单。
- 需要独立端到端测试后才能交付；其他格式显示明确不支持。
