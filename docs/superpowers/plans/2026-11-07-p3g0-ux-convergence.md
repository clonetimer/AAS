# P3-G0 实施计划

> 依赖：先取得 P3-F 完整源码候选包并校验哈希，再从该包建立本地 worktree。当前 GitHub AAS 仓库为 Public，不能在未经用户确认的情况下上传完整应用源码。

## Task 0 — 恢复真实源码基线
- 从用户存储空间/本轮附件取得 P3-F ZIP。
- 核对独立提供的 ZIP SHA-256、CRC 和逐文件 manifest。
- 检查其 Git 状态、P3-F 提交、工作区是否干净。
- 仅从已验证 ZIP 创建 feat/aas-p3g-ux-convergence 本地分支。
- 若 ZIP 不可取得，不在旧 P3-E 文档分支上伪造源码实现。

## Task 1 — 首页与导航
- 先增加 Node DOM 契约测试，验证唯一历史库入口、导航分组、旧路由兼容。
- 核对首页任务统计 API 与任务中心统计口径。
- 修改前端导航和首页，不删除后端页面。
- 执行 Node 测试和任务历史 API Python 回归。

## Task 2 — 任务流程向导
- 增加向导状态模型和 Node 测试。
- 复用现有导入、数据预检、故障模拟、训练、评估/推理 API。
- 验证无标签数据与监督评估隔离。
- 验证返回上一步和页面刷新时的安全状态恢复。

## Task 3 — CSV 导入统一外壳
- 先对四种用途建立现有 API/校验能力矩阵。
- 建立共用前端向导组件，但保留各用途独立后端 API。
- 测试编码、分隔符、字段映射、文件变更重新预检和错误定位。

## Task 4 — 故障参数解释
- 为每种故障类型建立单一参数元数据定义（标签、单位、范围、默认值、数学语义、示例）。
- UI 从元数据渲染，避免前后端两套定义漂移。
- 对 CSV 与历史模拟模式分别声明支持范围。
- 使用测试校验参数语义和闭区间帧号。

## Task 5 — 页面状态连续性
- 建立版本化、白名单化、大小受限的 UI draft 状态模型。
- 仅持久化筛选条件和用户配置草稿，不持久化敏感运行对象。
- 文件 hash/大小/修改时间或来源快照变化时，旧预检失效。
- 增加刷新、切换页面、草稿恢复、取消离开测试。

## Task 6 — 全链路用户验收
- 由未参与开发的测试人员执行导入→预检→训练→评估→报告。
- 记录完成率、时间、错误次数、求助次数。
- 整理 P3-G0 缺陷，完成后进入 P3-G1 实验结果解释。
