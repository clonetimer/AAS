# P2 历史数据库减负、历史模拟逐帧化与可继续注入

基于 `docs/superpowers/specs/2026-11-05-aas-v2-upgrade-design.md` 和 P0/P1A/P1B 已验证实现。每个任务先补失败测试，再作局部改动，验证后提交；不破坏原始数据库、既有模型契约或退役路由。

## Task 1 — 历史故障模拟结果全表导出

- 为已经保存的 `v2_injection_records` 增加按 ID 读取完整保存采样的 CSV 导出 API（服务端鉴权、无预览行截断）。每条记录是单参量派生数据，CSV 应包含原始顺序、帧号、时间、注入值、已知注入标签及来源元数据；不得伪装成历史全星遥测表。
- 历史记录行提供导出控件，保留删除按钮。
- 回归：真数据库保存导出、长于预览上限、失效 ID、认证拒绝。

## Task 2 — 历史模拟按帧选区及历史记录的二次注入入口

- 历史页的注入位置改为一基、闭区间 `[开始帧, 结束帧]`，同时保留 `max_points` 作最多读取帧数；后台兼容现有 `onset_s` 请求以支持已有工具和保存数据。
- 扩展事件计算与预览标注到所选帧区间（不是将尾部全部误标），保存原有正常/故障来源证据。
- 已保存的历史模拟可以直接「继续注入」：经全量导出生成新的 CSV 工作区原始版本，由用户继续按帧叠加，并明确历史旧记录并不被修改。
- 回归：首帧、末帧、越界、间隔、不改源、导出再导入版本链、UI。

## Task 3 — 历史浏览筛选约束分级

- 浏览页面补足 `raw`、`unspecified` 等实际角色；解释浏览不等于训练资格，不猜测正常/故障真实标签。
- 给浏览查询使用 `coverage_mode=union`，允许选择时间范围不重叠、但时间域一致的多条曲线分别展示；训练/评估旧接口严格交集和真实时域边界保持不变。
- 日期过滤仍严格拒绝不存在的时间范围；对不同时间域和来源冲突显示可操作提示。
- 回归：浏览角色、并集边界、无重叠绘制、默认现有交集不变、网页契约。

## Task 4 — 专项 UX 验收、证据说明与交付范围更新

- 结合公开成熟数据实验工具的导入预检、实验版本、可追溯报告与易恢复操作，写给现场非程序员的行为说明。
- 跑 P0～P2 综合回归、静态脚本验证、记录遗留基线/Windows 待测；完成 commit。
