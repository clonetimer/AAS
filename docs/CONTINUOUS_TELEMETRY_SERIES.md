# 按逻辑参量连续查看跨表遥测数据

## 为什么不合并成一个大表

原有的每表单参量模型可以保留。物理表只是某个参量的一段采样数据/导入批次，不应成为用户浏览的基本查询单位。一个巨大的宽表会引入不同采样率、时间戳对齐、缺失值和扩展参量的问题；一个巨大的通用窄表虽然可行，但不必为浏览跨表时间范围而立即做物理迁移。

这次采用**同一数据库内的逻辑参量（虚拟时间序列）**：以完整身份 `(model, subsystem, device, variable)` 选取多个单参量来源表，在 SQLite 查询期 `UNION ALL` 并按 `timestamp` 排序，返回虚拟的连续视图，不写入任何物理合并表。若将来同一数据库中放置多颗同型号、同部件的卫星，应在身份目录中先增加卫星实例 ID；此版仍使用当前已有的四级身份。

## 使用

在「数据浏览」选数据库后，使用左侧「按参量连续查看（自动跨表）」的四个级联选项，点击「查看完整参量时间序列」。系统会在当前数据库中自动定位这个参量的全部符合规范的单参量表。此后使用右侧「查看时间段」指定任意跨表起止时间，无需手动勾选物理表。明细里 `source_table` 保留每条采样行的来源，顶部明确列出参与窗口查询的表。点击「返回物理表视图」可继续使用原有的多参量表对比、故障区间编辑、预处理等功能。

**限制及质量规则：**

- 仅限同一个 SQLite 数据库。跨数据库（或卫星实例）联合检索尚未实现。模型、分系统、部件、参量四个字段必须完整匹配，不能仅以参量名合并不同设备的记录。
- 只读取标准的 `timestamp/value/label` 单参量业务表。旧式多列测量表不能被自动当成单参量并入。
- 按时间查询，**无数据的时间段仍为空，不插值、不生成虚假采样**；在已加载的曲线上，超过可观察常见采样间隔三倍的时间空洞会断线。
- 重叠分片具有相同时间戳且 `value/label` 相同的采样只显示一次，并统计重复数量；同一时间戳的数值或标签冲突直接拒绝查询，必须在原表层核对数据。来源选择是可复现、确定性的（按物理表名字典序），不代表覆盖/修改原记录。
- 不接受混合数字/文本时间轴和不同格式的 ISO 文本分片；时间戳规范化及统一时区由导入数据管理流程负责。本功能不会擅自修正时区。
- 当前一次展示最多 5000 条，接口支持分页、返回 `matched_count` 和 `truncated` 以明确告知截断。应缩小时间窗查看详细波形。`total_count` 为来源物理行数（可能包含重复），不是全时段去重逻辑行数。
- 按逻辑参量浏览时**不启用跨表写入操作**：故障事件区间编辑、数据预处理、删除都仍针对实际物理表。虚拟视图不更改各来源 `label`、故障标注或数据用途（训练/测试）。
- 与「不同参量按时间戳对齐生成临时特征矩阵」相互独立。逻辑参量浏览不会悄然改变已有多特征训练/评估的输入表契约；第二阶段通过单参量专用契约增加了跨分片训练/评估。

### API 示例

```http
GET /api/telemetry-series?db=datasets/history_sample.db&model=DEMO&subsystem=ADCS&device=demo_unit&variable=temperature&start_time=2026-01-01%2000%3A00%3A00&end_time=2026-01-02%2000%3A00%3A00&limit=5000&offset=0
```

返回 `columns`、`rows`（包含 `source_table`）、`sources`（各表首尾和本窗口命中行数）、`min/max`（参量跨表总范围）、`matched_count`（去重后命中行数）、`duplicate_count` 和 `truncated`。空窗口仍会返回所有可用来源的时间元信息。

## 第一阶段遗留的海量数据改进建议（部分已在第二阶段实现）

第一阶段采用只读、按需发现，不更改数据库结构。第二阶段通过可选的显式索引刷新增加了精简覆盖目录；生产规模继续演进时可以扩展 `aas_series_partitions`（`variable_id, table_name, start_time, end_time, sample_count, timestamp_kind, data_role, source_id, ingest_batch_id, checksum, updated_at`）。导入/删除时事务性更新目录；建 `variable_id + start_time + end_time` 组合索引，并为各实际采样表建立 `timestamp` 索引，查询先进行时间覆盖剪枝，再以 `UNION ALL` / 有序流合并取数。真实卫星还需明确卫星实例、UTC/统一时基、时间戳精度与时钟质量，才能谈“参量唯一”。

真正需要改变物理存储引擎或规模到亿级以上的数据量时，再评估 SQLite 分片、Parquet/DuckDB 或专业时序库。**是否更换物理存储，应由测量规模、写入并发和查询负载决定，而不是因为浏览器暂时无法跨表查询。**

## 第二阶段：训练、评估与导出（2026-10-20）

### 训练页

进入「模型训练」→选择数据库及该参量的任意一个**有效训练集**物理分片→勾选「按当前参量自动拼接所有训练时间分片」。训练页的开始/结束时间作用于**所有训练分片组成的逻辑时间序列**，然后按全局时间顺序依比例划分训练/验证。图形预览展示跨表前最多 1200 行；实际任务读取完整指定时间窗，最多 250000 行，不以预览行数作为训练上限。数据加载过程只接收目录身份完全一致、标注为 `train` 且角色验证通过的表；`test` 表绝不参与训练。

当前仅支持**单参量、`value` 单特征、原始数据、样本 `label`、按时间比例划分**；不能与「附加训练数据表」多特征对齐、独立训练/测试表组或清洁数据视图混用。跨表逐表预处理和**不同逻辑参量之间的时间对齐**尚未开放。模型的 `data_contract` v4 保存逻辑参量身份、物理分片清单、查询范围，以及实际加载结果的 `logical_series_manifest`；数据仍不会写到合并物理表。

### 评估页

选择已发布的**单参量原始数据模型**和有效测试表，勾选「按当前参量自动拼接所有测试时间分片」；可独立指定评估开始、结束时间。评估时仅使用相同逻辑身份且用途为 `test`、标签有效的分片，**按合并后的整个测试序列**校验是否同时存在正常与故障样本；单个分片可以只有一种标签。纯正常分片若被自动识别为训练用途，必须先在数据管理中明确标记为 `test` 才能并入逻辑测试集，不加入训练分片；同一时间戳的数据/标签冲突必须先解决。仍使用发布模型的检测器和训练期模型输入归一化参数，不重新执行 `fit()`；事件区间标签映射目前仍只在物理表模式使用。

训练、评估期间会重新检查实际来源表归属与用途。如果异步任务创建后分片清单变化，拒绝继续，而不是悄然读入新表。任务执行记录还包括所有选中物理表的行内容指纹；此哈希代表观察时的数据，不等同于数据库正在发生并发修改时的事务级输入快照。

### 数据浏览页：跨表时间窗导出

选定「按参量连续查看」并输入起止时间后，点击「导出该参量的指定时间范围（ZIP）」。ZIP 含 `telemetry.csv`（真实全量符合时间窗的时序记录，含 `source_table`）和 `manifest.json`（逻辑身份、时间窗、来源分片、行数、去重数和标签语义）；通过一个 SQLite 读事务取得一致数据。不会修改原始表，也不会在数据库中创建永久联合表。单独物理表的 CSV/ZIP 导出功能保持不变。

### 大数据范围：显式分片覆盖索引

支持建立 `aas_series_partitions` 物理分片覆盖目录，记录身份、每张表的 `MIN/MAX(timestamp)`、物理样本数及时间戳类型，创建身份及时间范围组合索引。此优化**不会自动修改既有业务库**，数据库管理员备份原数据库之后，可通过同源认证的 POST API 手动刷新：

```http
POST /api/telemetry-partitions/refresh
Content-Type: application/json

{"db":"datasets/history_sample.db", "confirm":true, "with_timestamp_indexes":false}
```

对于大数据量，设置 `with_timestamp_indexes=true` 会额外为每张支持的物理表创建时间戳索引，首次构建可能花费时间、占用磁盘，应在离线维护窗口执行；默认不开启物理时间索引。

分片目录附带针对每张源表的 `INSERT/UPDATE/DELETE` 触发器。源行一旦被改动，目录缓存会在同一事务内被标记为 `dirty`；查询此时**自动回退扫描源表**，确保不使用旧边界排除新数据。之后管理员可以显式重新调用刷新接口。新导入的表因为未登记，也会参与标准扫描。删除的物理表也不会从缓存中被读取。没有索引时，原有查询继续正常工作。

这一版虽然能对时间窗不相交的分片提前剪枝，但多分片逻辑联合和导出仍需计算去重/冲突计数，且大量分片时存在 UNION 与 OFFSET 分页成本。**不宣称支持无限分片或亿级实时查询**；需要基于实际数据库规模再评估游标式归并、分区级摘要，以及 Parquet/DuckDB 等查询引擎。

### 下一阶段的能力边界

1. 多卫星实例 ID、原生时区归一化、时间戳质量标识与时钟漂移校正，以及真正跨多个 SQLite 数据库的参量发现。
2. 跨表故障区间编辑、跨表预处理与完整的物理分片生命周期管理；原有物理表编辑功能不变。
3. 多逻辑参量融合的事件区间标签映射、缓存复用、流式归并和超大规模分片索引优化。


## 第三阶段：多个逻辑参量的联合训练与评估（2026-10-20）

例如 RW1 转速分在 speed_train_1/speed_train_2，电流分在 current_train_1/current_train_2。选择「转速」和「电流」两个逻辑参量（在界面中各选其中一张代表物理表），服务端按完整四级身份与 train/test 用途分别读取各自的时间分片，独立去重并检查同参量重叠时间冲突，然后才将两条逻辑时间序列按时间戳对齐为 `value, source_2` 两列。不会建立永久大表。最多选择 16 个不同逻辑参量。

### 操作流程

- **训练：** 在模型训练页选择训练数据库、主参量物理表，在「附加训练数据表」中每个其他参量选择一张代表物理表，勾选「多参量跨表连续融合」。保留「单参量自动拼接」关闭。选择原始数据视图、按时间比例划分，设定可选时间窗及时间同步方式。点击同步预览查看匹配样本数、各参量样本利用率及来源身份，确认后训练。
- **评估：** 对使用该模式训练并发布的模型，评估页可识别模型输入模式并勾选「按多个逻辑参量联合评估」。为模型的每个特征选择一个测试参量的代表表，特征的**位置和数量**必须与模型完全一致。各测试参量会自动读取它自己的全部有效 `test` 分片；使用训练模型保存的对齐参数及模型输入归一化状态，绝不重新拟合检测器/Scaler。评估曲线预览仅显示第一个逻辑参量，不代表已融合的全部特征。
- **来源契约：** 模型 `data_contract.version=5` 包含有序 `logical_multi_sources`（逻辑身份、全部来源表）、`alignment`（每源样本数、来源表、时间类型、匹配率、特征次序与标签策略）。实验 `execution_provenance` 现在对 **所有** 来源物理分片进行前后行内容摘要，而不只是两张代表表；有效模型输入矩阵仍由 `input_evidence` 记录。

### 校验与防泄漏边界

- 不允许混用物理表多特征融合、单参量逻辑模式、清洁数据视图、双表严格训练模式；源表必须有完整的 `(model, subsystem, device, variable)` 身份及 `timestamp/value/label`。训练物理分片必须用途为 train 且数据仅正常，测试物理分片必须明确用途为 test 且标签为 0/1；按全部对齐样本验证测试标签包含两类（即使单个测试参量始终正常）。
- 采用已有匹配引擎：严格同时间戳匹配、最近邻（一对一）、过去观测保持（previous），可选固定时间轴和有界容差。不根据行号对齐，不对时间空洞进行插值；不允许同一逻辑参量重复作为不同输入特征；同一参量分片重叠而标签或数值冲突会直接报错。
- **在线/实时或因果实验请选择 `previous`，并配置正数容差**。`nearest` 允许使用时间上位于主时间轴采样点之后的观测，适合明确允许的离线实验，不适合声称实时因果诊断的训练与评估。固定时间轴的范围外容差匹配会按现有引擎规则保留原始邻近点，故此模式目前会读取全部候选分片再筛选；主参量时间轴则支持在物理表层按窗口范围裁剪。
- 训练数据按对齐后的全局时间序列划分训练/验证，不重新打乱。**训练和测试数据的逻辑用途隔离不等于所有形式的数据泄漏都自动消除**：用户应根据算法的时间感受野控制训练/验证边界；不允许用评估标签拟合或重新估计归一化参数。
- 每个逻辑参量最多读取 200,000 个窗口内（固定时间轴为候选全量）去重采样，超出需缩小范围或归档；固定时间轴最多 200,000 网格点。同一 SQLite 数据库内查询、不会自动创建分片索引，也不自动修改原始数据库。
- 不支持多逻辑参量的事件区间标签映射（`interval`）；如果逐样本标签不完整，请先在物理数据层明确标注，不能凭空认定缺失标签为正常。AAS 仅融合、保存、展示与计算结果，报警持续时间/阈值判决由具体检测算法负责。

### 调用契约（概要）

训练 `/api/train-model` /现有训练任务接口中使用 `logicalSources: [{model, subsystem, device, variable}, ...]`，同时 `sourceTables` 为一参量一张代表表（相同有序维度）；单参量 `logicalSeries` 必须为 null。评估 `/api/evaluate-model` 使用 `logicalSources`、对应 `tables` 代表表列表和可选 `evalTimeStart/evalTimeEnd`。`GET /api/train-alignment-preview` 追加 `logical_multi=true` 以预览相同融合策略和质量指标。具体路由沿用现有 HTTP 认证与受管数据库路径检查。
