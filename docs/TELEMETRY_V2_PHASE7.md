# V2 Phase 7：完整源码、全新仿真历史库与预处理/事件叠加

## 交付策略

Phase 1～6 的更新文件已完整合入原始 AAS 源码。没有逐次增量安装依赖；旧历史数据、旧样例表及四个原 SQLite 数据文件均不包含。工程自带唯一新的 `datasets/aas_telemetry_v2.sqlite`，原始 19 个 `.csv.gz` 作为可核验来源数据保留。

## 数据建模

每个压缩文件包含 `time_s` 和 56 个遥测列。每个文件是独立的仿真运行，统一登记 `role=simulation`，用文件标识作来源命名空间和临时 satellite_instance。对于 `adcs.rw.measured_speed_rad_s_0`，逻辑归属为子系统 `adcs`、部件 `rw`、变量 `measured_speed_rad_s_0`，完整原始列名保存在 `v2_segments.source_table`。

新库采用 V2 既有 `v2_sources / v2_channels / v2_segments / v2_samples` 模型，新增 `v2_upload_manifest` 记录原始头字段、来源哈希和数据说明。每条分片对应 `v2_segment_clock`，时基为 `elapsed_run:<文件标识>`、单位为 `s`。不同运行的相同秒数不合并，源码不会猜测卫星型号、绝对时间、故障标签或数据用途。

## 原生预处理

- `POST /api/v2/telemetry/preprocess/preview`：参数 `channel_id,role,method,params,start,end`，只读检验并返回首批派生结果。
- `POST /api/v2/telemetry/preprocess/commit`：增加 `confirm: true`，服务端以原数据指纹重新验证来源后执行事务写入。
- `moving_average` / `median_filter`：当前与历史样本构成的因果窗口，窗口 2～501。
- `difference`：相邻两个实际样本的值差，第一条不伪造为 0；不代表单位时间变化率。
- `clip`：显式传入有限数值 `min` / `max`。
- `zscore`：**只能由明确的 train 用途数据拟合**；仿真、原始和测试用途禁止拟合，以避免测试统计信息泄漏。

写入时创建新的来源命名空间、逻辑参量和 `v2_preprocess_jobs` 溯源配方（方法、参数、输入哈希、拟合参数、操作者）；不覆盖原分片或样本标签。仿真/原始输入的结果用途为 `processed`，训练/测试输入的派生结果分别保留其用途。源数据超过 100,000 点须缩小时间窗。结果没有替代正式训练/测试划分的权能。

## 事件区间绘图

浏览页每次成功加载曲线后，通过现有 `/api/v2/telemetry/events?channel_id=...&role=...` 读取已确认有效的事件；按 `[start,end)` 在对应参量所在的独立绘图轨道绘制红色故障/绿色确认正常半透明条带和悬浮详情。未标注则无覆盖。若事件接口失败，仍绘制基础遥测，视为注释不可用而非“无故障”。

## 限制和后续验收

1. 源数据没有故障标签及训练/测试数据集声明，当前新库不能凭这批 CSV 直接完成有监督训练和测试评估；需后续明确来源、完成数据划分与标签管理。
2. 上传文件名是哈希字符串，无法仅凭文件名判定同一卫星型号/实体，因此按独立运行登记。用户提供任务元数据后可另行修改参量身份映射。
3. 当前完整包仅通过本地相关单元/接口回归、数据库完整性和 JS 语法检查；Windows 浏览器实机及全新稳定门禁未完成。
4. 数值时间戳是仿真相对秒，不会变成真实 UTC 日期；事件必须与当前运行的时基一致。
5. 本次不会删除用户设备中的任何旧数据库文件；“全部删除”作用于本次交付的新建数据库与源码交付内容。
