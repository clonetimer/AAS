# 单参量数据表与多表联合分析

## 一、数据表组织

系统按“型号 → 分系统 → 部件 → 参量 → 数据表”组织历史与模拟数据。每张数据表只有一列**业务测量值** `value`，此外须有 `timestamp` 和 0/1 `label`，并用 `model`、`subsystem`、`device`、`variable` 标识采样对象与参量身份。

建议按数据来源及用途分别创建数据表，例如 `RW_speed_train` / `RW_speed_test`、`battery_soc_train` / `battery_soc_test`。多张表的标签**分别维护**；对单参量表标注的故障不自动传染到其他表。

原始 CSV/JSON 若包含多路传感器数值，不应作为单张业务表导入：请在导入时按参量拆分为多张表，确认各表保留对应 `value`、时间戳与标签。既有多列旧表不会被自动删除，其额外数值列也不会参与本轮多表训练。

## 二、曲线查看

如果要查看**同一参量的多个时间分片**（例如一张表存上旬、另一张表存下旬），请优先使用数据浏览左侧「按参量连续查看（自动跨表）」：选择完整四级参量身份，再选择总时间范围。该功能按时间拼接多个物理表，并保留记录来源；不是下面的不同参量叠加对比。详见 [跨表连续查询说明](CONTINUOUS_TELEMETRY_SERIES.md)。


进入「数据浏览」，选择数据库后点击「选择数据表 / 比较曲线」。统一弹窗提供关键词搜索、型号/分系统/部件/参量筛选、已选项保留和顺序调整；最多叠加 8 张数据表。勾选后可在「主数据表」切换预处理、明细表和故障记录的操作对象；重置全部筛选不会删除任何数据。数据浏览的明细表、故障列表和数据预处理操作仍**针对第一张主表**，不是对全部选中表批量修改。

横轴采用各张表的真实时间戳；各线的纵向位置基于其自身原始最小/最大值映射到绘图区。选择「Y 轴参考表」时，仅左侧刻度切换到那张表的真实量纲，线条形状和位置不会变化。**其他线不能直接用当前 Y 轴读数。** 各条曲线的原始范围可以在图例中查看。时间窗口过滤是浏览用途，训练时请在训练页另外选择时间范围。

## 三、联合训练

在「算法运行」点击统一选择器，一次选择并排序正常训练表；系统逐表获取 `timestamp,value,label`，默认以主表时间戳为锚点，也可生成独立的固定周期时间轴，再通过选定规则生成临时训练矩阵。主表是模型输入第 1 列，附加表按勾选顺序依次成为后续列。页面展示共同时间点数和各表对齐覆盖率。建议先查看该信息后再启动任务。

每表必须具有明确、唯一的型号/分系统/部件/参量身份。重复时间戳、无有效重叠、非法标签和不足以划分的样本均会报错，而不是默默按行号拼接。默认界面先给出**最近观测 + 5 秒最大偏差**的建议配置，开始训练前应检查覆盖率和采样周期；设为 0 秒则恢复严格时间戳匹配。最近观测按主表时间轴一对一匹配，可能取到略晚于主表时刻的数据，因此只建议用于离线评估。另一种「上一有效观测」严格选择主表时刻之前或同时发生的观测，允许在指定有效期内重复使用旧值（零阶保持），支持不同采样率的因果对齐。无论哪种方式，原数据表均不改变，也不做隐式插值。超出最大偏差的时刻被舍弃。训练页提供对齐后样本数、逐表覆盖率和最大时间偏差。统一时间网格有效率低于 80% 时，训练需要人工确认；低频传感器的原始样本利用率与网格有效率分别统计。训练时后端会重新校验匹配结果。该匹配算法采用时间单调的贪心规则，不保证全局最优配对。

**重要边界**：「最近观测」模式不能直接用于实时在线推理，因为可能引用未来观测。「上一有效观测」提供不使用未来信息的时间对齐前提，但实时部署还需要显式时钟偏差、消息到达延迟、缺测和数据有效期设计。标签取所匹配各来源标签的 OR，并不自动证明在同一真实时间发生故障。不同参量采样频率差异过大、故障切换很快、存在已知采样延迟时，需先做显式采样策略和标签区间审查。现在还支持**固定周期统一时间轴**：在「统一时间轴」中选择「固定周期」，填写输出采样周期（秒），系统在各参量共同覆盖的时间范围内生成临时时间网格，再按「最近观测」或「上一有效观测」逐点取样。该网格不是数据库物理表，界面提供有效网格比例、原始观测利用率、逐来源匹配时刻与标签预览。当前不做数值插值；无法匹配或超出容差的时间点丢弃。标签可选择「匹配观测的标签」或「上一有效标签」，二者均不插值，多个来源的标签按 OR 形成联合标签；后者限定使用时间网格当前及过去的标签。固定周期输出点数最多 200,000，每个参量的输入上限同为 200,000 行。**固定时间轴不会自动提升诊断准确率，输出采样周期与有效期应由传感器采样和诊断任务决定。**

可指定起止时间，仅使用该窗口内的数据，之后按时间顺序划分正常训练集与验证集。联合训练需要检测算法能接受多维矩阵；不支持多维输入的算法应明确报错。

## 四、测试和标签

训练表要求仅正常 `label=0`。已发布模型评估优先匹配与训练参量身份相同的测试表；跨设备、型号或参量评估时，直接选择目标表并确认特征顺序，系统会自动记录源/目标差异，无需额外开关。模型重用训练时保存的特征顺序、处理方式、时间容差和归一化参数，不能在测试阶段重新拟合。

同一时刻若任一表标签为 1，则联合评估样本标签为 1（OR 规则），各表原始标签也被保留以便复核。此规则只能用于检测“至少一个源故障”，不能直接解释为故障定位或因果归因。如果实际任务要求分系统故障定位，应保留每个表的真值，建立显式故障模式映射，不要直接把 OR 标签作为部件故障类别。

## 五、示例和工程边界

演示历史库 `datasets/history_sample.db` 内新增 4 张正常单参量训练表和 4 张独立测试表。四个参量分别为 `temperature`、`vibration`、`current`、`pressure`，训练表每张 480 条，测试表每张 180 条。这些是**合成测试数据**，用于确认软件接口、曲线和联合训练流程，不代表真实故障算法性能。

当前多表训练采用时间比例划分；评估页支持独立的多表测试组。当前提供有限时间偏差的最近观测匹配、因果样本保持和固定周期临时宽表；不提供隐式线性插值、跨数据库连接或自动跨域特征映射。单次浏览最多展示 8 条曲线，联合训练最多 16 张表，每表最多读取 200,000 条记录，超出时需先按任务划分数据。

## 多逻辑参量跨时间分片联合训练（Phase 3）

在模型训练页勾选「多参量跨表连续融合」，主表和每张附加表代表**不同参量**；系统自动检索每个参量所有符合角色约束的分片，然后执行时间对齐。切勿把同一个参量的多个时间分片当作不同特征。多逻辑参量训练/评估的选项、容差、来源契约与限制，见 [连续遥测设计文档](CONTINUOUS_TELEMETRY_SERIES.md)。
