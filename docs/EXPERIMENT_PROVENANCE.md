# 训练与评估结果溯源

AAS 的历史报表由服务端完成的训练任务或已执行的模型评估创建，不再将浏览器上传的指标或异常分数视为可信结果。

## 使用方式

在工作台正常执行训练或评估。执行成功后，服务端返回短期、一次性 `execution_receipt`；浏览器将其提交到 `/api/save-experiment`。凭证有效期为 30 分钟，一旦保存成功便不可再次使用；重启服务后未保存的凭证失效，需要重新执行任务。

每份新报表保存在 `outputs/experiment_<id>/reports/`，包括：

- `summary.json`：指标、抽样曲线、当次故障事件快照、`provenance` 元信息。
- `execution_result.json.gz`：服务端产生的完整评分输出，未使用曲线展示下采样代替原始结果。
- `execution_config.json`：完整执行请求配置（包括时间窗口和同步策略），供复现核对。

`provenance` 记录执行时间、实际算法实现文件集合的 SHA-256、Python 与主要依赖版本、训练配置摘要、完整服务端结果摘要、执行前后所选物理数据表的逐行摘要，以及模型工件摘要（若适用）。历史结果与实验源数据不共用可修改的图表缓存。

可使用下列命令核验已保存的完整结果文件与历史摘要是否一致：

```bash
python scripts/verify_experiment.py outputs/experiment_<id>/reports/summary.json
```

输出 `verified_archive_digest` 表示**归档内部摘要一致**，不是外部签名或模型科学正确性的证明。

## 重要边界

1. 本功能不替算法制定阈值、连续告警、去抖或其他决策策略。算法输出保持原样。
2. 输入数据摘要使用所选**物理表全部记录**；它是在执行前后计算的快照，不等于训练时某个内存预处理张量的字节摘要。若数据在执行期间改变，报表会记录 `input_changed_during_execution`。
3. 不能单凭 SHA-256 或依赖版本保证跨机器严格复现实验。模型的随机种子、系统底层依赖、GPU 确定性、时间窗口、预处理逻辑及执行环境仍可能影响结果。
4. 旧报表没有服务端执行凭证，历史展示标记为“无服务端执行溯源信息”，不伪造摘要。
5. 已运行任务若因服务器关闭或浏览器断开导致保存失败，可重新执行任务；凭证不跨服务器重启持久化。
6. `save-experiment` API 自本次更新起**必须**提交 `type` 与有效 `execution_receipt`；历史客户端直接提交 `result` 的方式被拒绝。这是有意的安全契约升级。
7. 数据库、模型与归档文件都由有权限的本地操作者管理。没有外部可信签名时，拥有文件修改权限的人也可能同时修改内容和摘要；如需防篡改审计，应将摘要推送到独立只追加存储。
